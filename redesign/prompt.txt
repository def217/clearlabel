## Design intent

The page must read like a **printed regulatory document or a standards-body notice**, not like a SaaS
landing page. It is deliberately anti-"AI-generated-website". Obey these prohibitions absolutely:

- No gradients of any kind (no gradient backgrounds, no gradient text, no gradient borders).
- No glassmorphism, no blur effects except one subtle backdrop blur on the sticky header.
- No large border radii. Maximum radius anywhere is `2px`. No pill-shaped cards.
- No drop shadows at all. Separation is done with 1px hairline borders and background tone shifts.
- No emoji, no icon badges in coloured circles, no decorative illustrations, no hand-drawn SVG.
- No centred hero. No three identical feature cards with an icon on top.
- No purple/violet/indigo palette, no neon, no dark-mode-glow aesthetic.
- No "Trusted by" logo strip, no fake testimonials, no animated gradient orbs.
- Never use the fonts Inter, Roboto, Poppins, Montserrat, or Arial.

## Behaviour and accessibility requirements

- Define `a` and `a:hover` colours explicitly (`#22407c` -> `#1b1a16`); never leave browser-default blue.
- Visible focus ring everywhere: `:focus-visible { outline: 2px solid #22407c; outline-offset: 2px }`.
- Body text contrast must clear WCAG AA against the paper background; do not lighten the muted greys further.
- Every interactive element is a real `<button>` or `<a>` — no clickable `<div>`s.
- The countdowns must never render as `0`, `NaN`, or a dash on first paint; compute them synchronously.
- Keep it dependency-free: no CSS framework, no icon library, no animation library. Plain CSS is fine —
  a single stylesheet is preferable to utility classes.
- No layout shift when the accordion opens or the scan panel changes state; reserve the panel's height.
- Respect `prefers-reduced-motion`: the only motion in the design is smooth anchor scrolling and the
  scan-status text updates, so disable smooth scrolling when it is set.

Deliver the complete rebuilt page as production-ready HTML + CSS (plus the minimal vanilla JS for the
countdowns, the scan-status panel, the accordion, and the copy button), preserving the existing scanner
implementation and all current URLs. State any assumption you had to make in a short list at the end
instead of inventing content.

## Integration contract (important)

The existing scanner is an ES module at `./app.js` which imports `scanHtml` and `assess` from
`./scanner/core.mjs`, fetches the target page through a CORS reader chain, and returns an object shaped:
`{ url, vendors:[{id,name,aiNature,aiProduct,vendorDocs,disclosureHook,foundOn}], disclosures:[{lang,phrases,context}],
contentSignals:[...], pagesRead:[...], overall:'action-required'|'check-required'|'likely-ok'|'no-signal',
findings:[{article:'50(1)'|'50(2)', status, confidence, title, detail}] }`.
Do NOT reimplement fetching or fingerprinting. Emit the markup with stable ids/data attributes and a
documented set of hook points (e.g. `#scan-form`, `#scan-url`, `#scan-submit`, `#scan-phase`,
`#check-vendor`, `#check-disclosure`, `#check-marking`, `#scan-result`) that existing JS can drive.
Output the HTML file first, then the CSS, then the JS, each in its own fenced code block.
